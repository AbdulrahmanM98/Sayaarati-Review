# Sayaarati Review

### Information Systems Capstone | Requirements Analysis · System Design · Web Prototype

**Sayaarati Review** is a university graduation project that explores a car-information and community-review website. The idea is to help people researching a car find vehicle details, compare options, read other users’ experiences, and contribute reviews in one place.

**Project type:** Academic team project — King Abdulaziz University, Department of Information Systems  
**Portfolio focus:** Project coordination, requirements gathering and specification, system modeling, testing and documentation  
**Status:** Completed academic project; the team-built website remains available at the project link below, as reported by the contributor.

## Problem & Objectives

The project report identified difficulties in navigating existing car-information websites, inconsistent or insufficient vehicle information, and the challenge of choosing a car without accessible user feedback. The proposed response was a car-review platform combining browsing, search, vehicle information, community ratings and reviews, with chatbot assistance.

The documented objectives included presenting detailed vehicle information; enabling users to share and read reviews; improving discovery and comparisons; and exploring personalization and user-engagement analysis.

## Requirements & Research

The team surveyed prospective end users about review-related features. The final report records **29 responses** to the five closed questions and **12 responses** to an open question. Among the 29 responses:

| Question/theme | Answer recorded as “Yes” |
|---|---:|
| Include maintenance and repair costs in reviews | 28 / 29 (96.6%) |
| Allow users to react to others’ reviews | 22 / 29 (75.9%) |
| Save reviews for later | 27 / 29 (93.1%) |

These are **results from the project's small academic survey**, not representative market research.

The report documents functional requirements for account registration and login, car search, reading and writing reviews, administrative content management, and car-listing management. It also specifies non-functional goals covering usability, security, efficiency and availability. Some items are proposed system requirements, not verified completed features.

## Prototype Highlights

The report’s implementation chapter discusses HTML, CSS, JavaScript, PHP, a relational database and a chatbot created using a ready-made tool configured with selected questions. It describes **HostGator** as the hosting environment. The report includes examples of signup, car listings, review input and chatbot responses. References in the report to alternative tools or future functionality are not presented here as confirmed implementations.
